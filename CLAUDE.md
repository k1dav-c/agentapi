# CLAUDE.md

Use these commands and conventions when working on AgentAPI with Claude Code (claude.ai/code).

## Project overview

AgentAPI is a Go HTTP server for Claude Code, Codex and Pi, driven through their structured
protocols (the native transport); it refuses any other agent at startup. The binary embeds a
Next.js chat UI.

## Build & Run

```bash
make build              # Build binary to out/agentapi (includes chat UI build)
go build -o out/agentapi main.go  # Build with existing embedded chat assets
make embed              # Build chat UI and copy into lib/httpmw/chat/ for embedding
make fmt                # Format Go code with gofumpt
make gen                # Regenerate the OpenAPI schema, the hub's schema and version (go generate ./...)
make lint               # Run all linters (Go, TypeScript, shellcheck, actionlint)
```

From the repository root, start chat UI development with:

```bash
cd chat
bun install   # Install chat dependencies
bun run dev   # Start the Next.js development server with Turbopack
```

Run `bun lint` from `chat/` in another terminal to lint TypeScript.

## Testing

```bash
go test ./...                           # Run all Go tests
go test ./lib/httpapi/...               # Run tests in a specific package
go test -run TestOpenAPISchema ./lib/httpapi/...  # Run a single test
go test ./e2e                           # Run e2e tests (smoke test)
go test ./internal/docscheck            # Check the docs' links, anchors and zh-TW twins
cd chat && bun test                     # Run the chat UI tests
```

Use `CGO_ENABLED=0` for tests. The project uses `testify` (assert/require) and `coder/quartz` for
deterministic time mocking. Tests are colocated with source files. E2E tests in `e2e/` use
`e2e/fakeclaude`, a scripted Claude Code. CI also runs `CGO_ENABLED=1 go test -race ./lib/...
./cmd/...`. CI runs on the repository's self-hosted Linux runner only; nothing tests macOS or
Windows, so check code for them by hand (`GOOS=windows CGO_ENABLED=0 go vet ./...`).

## Architecture

See [docs/architecture.md](docs/architecture.md) for packages, the data flow, events,
persistence and the security model.

### Message flow

1. User sends message via `POST /message`
2. The server passes it to the agent's adapter (`lib/native`)
3. The adapter reports structured events (messages, requests, settings, usage) through its Sink
4. The conversation reports them to the event emitter (`lib/convstate`)
5. SSE events (`GET /events`) stream message and status updates to clients

### Key packages

- **`lib/httpapi/`** — HTTP server (chi router + huma for OpenAPI). Routes: `/messages`, `/message`, `/status`, `/events` (SSE), `/queue`, `/tasks`, `/summary`, `/upload`, `/rich-messages`, `/timeline`, `/update`; the lists come a page of tasks at a time (`history.go`). It keeps routing, the huma operations, auth, CORS, SSE writing and the message queue, and wires `lib/convstate`, `lib/webhook` and `lib/workspacefs`, whose types it uses under their own package names: huma names a schema after the Go type, whichever package declares it, so no aliases are needed. `task_update` and `queue_update` go only to `/events?sync=1` clients; `summary_update` only to `/events?only=summary`, and `POST /tasks/seen` marks the tasks read for the summary's `unread`; `registry.go` keeps the server's registry entry. `update.go` updates the server through its API with `--allow-update` (`POST`/`DELETE /update`: install the latest release, wait for the agent to be idle, restart in place) and reports it in the summary's `update`. `spend.go` works out the summary's `spend` once a minute from `sessions.Store.Costs`, also by provider (`spend.providers`, the providers with calls in the last 7 days). Features that don't change the conversation are small modules with narrow dependencies (`fileAPI`, `terminalAPI`, `uploadAPI`, `authAPI`, `webhookAPI`).
- **`lib/httpmw/`** — The HTTP pieces the server and the hub share: the Host check and `--allowed-hosts`/`--allowed-origins`/`--bind` parsing (`hosts.go`), `CrossOriginProtection`, `Compress`, and `FileServerWithIndexFallback`, which serves the chat UI embedded via `//go:embed` from `lib/httpmw/chat/`.
- **`lib/convstate/`** — The conversation state clients read, without HTTP: the `EventEmitter` (messages, rich messages, timeline, requests, status; seq and epoch, subscriptions and replay), the tasks it derives (`tasks.go`: a user message and the agent's turn on it), the window it holds (`window.go`: with a state database the rich messages and timeline of the latest 100 tasks only, and `Page`, the pages of the lists and the full replay's latest 20 tasks), the summary (`summary.go`), the queue as the server reported it, and the `Persister` (`lib/statedb`) it hands every change to.
- **`lib/webhook/`** — Webhooks push events to a receiver: `Dispatcher` delivers them (queue, retries, HMAC signatures, heartbeats, `{ip}` in the public URL); `Observe` subscribes to the emitter (`Source`) and turns its events into task, request, message and tool events.
- **`lib/workspacefs/`** — What the file viewer reads of the working directory (`Dir`: content, diff through git, HTML preview, images, find). A refusal is an `Error` whose `Kind` `lib/httpapi` maps to 400, 403 or 404.
- **`lib/conversation/`** — Shared types, imported as `conv`: `conv.Message`, roles, status, error levels and validation errors, and the `Emitter` the native conversation reports changes to.
- **`lib/transcript/`** — The types of the structured transcript: rich messages (content blocks, images, usage) and timeline events.
- **`lib/agentlog/`** — The agents' session-log formats, one package each (`claudelog/`, `codexlog/`, `pilog/`): record types, parsers into rich messages and timeline events (the native adapters use them too), prompt and injected-context classification, model calls and file layout; plus line reading, the incremental file index and format-drift warnings.
- **`lib/sessions/`** — A server-held `Store` reads session logs incrementally for earlier sessions and history (`GET /sessions`, resume), subagents (`GET /subagents`, `GET /timeline?subagents=true`) and costs (`GET /sessions`, `GET /cost`). Each call counts toward its model provider (`ModelCall.Provider`, empty for the agent's own; `SessionCost.Providers`, `default` for it, with each provider's hours for the summary's `spend.providers`): Codex's log names it (`agentapi-<id>`, `codexlog.ProviderID`); a Claude Code call takes the provider of its session's latest provider-ledger entry at or before it (`Config.Providers`; a subagent's calls are its session's, a fork's copied calls the earlier session's), the agent's own without one.
- **`lib/providerlog/`** — The provider ledger, `provider-ledger.jsonl` beside the config file (`~/.agentapi/`), shared by the machine's AgentAPIs: `{"at", "agent", "session", "provider"}` lines appended in one write under `provider-ledger.jsonl.lock`, entries older than 90 days dropped (an `atomicfile` rewrite) at a process's first append and at most daily; `Sessions` reads what was appended since and starts over after a rewrite. `cmd/server` opens it (`httpapi.NativeConfig.ProviderLedger`); `lib/httpapi/provider_ledger.go` appends what `native.Config.ProviderUsed` reports, in the background.
- **`lib/pricing/`** — Model prices per million tokens, from the embedded `prices.json` and any additions or overrides in a `--prices` file. `Price.Cost` calculates a call's API-equivalent USD cost from its tokens. `bun scripts/prices.mjs <pi-ai>` compares `prices.json` with Pi's model registry (`--write` updates it); its header lists the prices added by hand.
- **`lib/native/`** — Native transport. `Conversation` turns the events of an `Adapter` (one per agent: `claude/`, `codex/`, `pi/`, plus the simulated `demo/`) into conversation state, requests (approvals, questions, plans) and login state, holds the queue for a usage limit stop or a failed turn it tries again (`hold.go`), and starts an agent that exits on its own again. Shared pieces: `agentio/` (the agent process and its loop, stdin writes, response matching, where the answer to an agent's request stands, lenient decoding with drift warnings, the snapshot throttle), `procutil/` (child process lifecycle), `IsAuthError`, `IsLimitError` and `IsTransientError` with `ClassifyFailure`, the order they count in for a failed turn, `ReadImage`; `nativetest/` has a fake adapter. `Policy` (`policy.go`) holds `--auto-continue`, `--retry-delays` and the restart delays with their defaults; `httpapi.NativeConfig` embeds it. Model providers (`provider.go`): an adapter that implements `ProviderRunner` starts on `Resume.Provider` and switches with `SwitchProvider`, or returns a `RelaunchError` (Claude Code back to its own provider; Codex always, `Carry`: a new thread with the conversation's text), for which `PUT /settings` uses `ApplySettingsAndRelaunch` to keep apply, prepare and start in one mutation sequence while `relaunchOnProvider` holds `s.mu`; `RelaunchError.Recovery` selects the previous known provider/model after an uncertain switch, which `recoverProviderLocked` starts by itself once a turn or compaction ends when the server couldn't relaunch then. `Config.ProviderUsed` gets a `ProviderUse` (session, provider, since when; `reportProviderLocked`) once a provider-capable agent started with its session known, when the session becomes known later, and after a switch in place, never for the session a fork copies; it is called under the conversation's lock, so the server appends it to the provider ledger in the background.
- **`lib/agentstate/`** — The values that describe a native agent's state and what it waits on: `Capabilities`, `LoginRequired`, `Settings`, `AgentUsage`, `Request`/`RequestState`, `LimitStop`, `RetryWait`, and `ConversationState`, the conversation's state the native `Observer` gets whole (`StateChanged`), with the `StoredState` that survives a restart. A new piece of state follows the checklist in `docs/architecture.md` ("Adding a piece of conversation state"). `lib/native` produces them; `lib/convstate`, `lib/instanceapi`, `lib/webhook`, `lib/statedb` and `lib/httpapi` use them without depending on `lib/native`. It imports only huma and `lib/util`, for the enums' `Schema` methods.
- **`lib/provider/`** — The model providers Claude Code and Codex can run on instead of their own (an Anthropic- or OpenAI-compatible endpoint such as a LiteLLM gateway): `Provider` (`OpenAIBaseURL`, `ClaudeBaseURL`), `Source` (the `providers` section of `~/.agentapi/config.yaml`, read again when it changes, then the hub's; the file wins on an ID; `Models` lists `<base_url>/models` when none are defined, kept 10 minutes; `httpapi.NativeConfig.Providers`), and `hub.go`: `HubSync` gets the hub's from `POST /api/providers/sync` every minute (first before the agent starts), signed with the hub's secret, sealed with AES-256-GCM under a key derived from it (`Seal`/`Open`) and bound to the request nonce so an old answer can't be replayed. Model-list redirects drop credentials on a cross-origin hop.
- **`lib/procenv/`** — The environment of the processes AgentAPI starts: the agent's, without the variables of an agent session AgentAPI runs in and AgentAPI's secrets (`ForAgent`), and the terminal shell's, which also drops AgentAPI's other variables (`WithoutAgentAPI`).
- **`lib/agenthome/`** — The directories the agents keep their state in (`$CLAUDE_CONFIG_DIR`, `$CODEX_HOME`, `$PI_CODING_AGENT_DIR` or their defaults), for the session logs.
- **`lib/statedb/`** — SQLite persistence of conversations (`--state-db`). `LoadRecent` loads the latest tasks' rich messages and timeline, and `history.go` reads earlier pages and goes through the timeline for `GET /timeline/export`. The stored state is one versioned (currently 2) meta value, `conversation_state` (`state.go`), with newer or unreadable envelopes preserved through later writes; the separate keys of 3.7.2 and earlier aren't read. A database AgentAPI 2 kept for a PTY agent opens: the agent starts a new session below its conversation.
- **`lib/instanceapi/`** — The contract between an AgentAPI and the clients that watch many: `WebhookInstance` (who it is, in its webhook events, summary and registry entry), `SummaryBody`, the webhook envelope with `Sign`/`Verify`, and `StateOf`, the state a hub shows of an instance. It imports only `lib/agentstate` and `lib/util`; `lib/hub`, `lib/registry`, `cmd/hub` and `cmd/list` use it instead of `lib/httpapi`. It also holds `AgentType`.
- **`lib/hub/`** — `agentapi hub serve`, which depends on `lib/instanceapi` and `lib/httpmw`, not on the server: instances join with signed webhooks (`webhook.go`), the hub follows each one's `/events?only=summary` (`watch.go`), keeps them in a file (`store.go`, with when the hub saw each working in `work.go`, and the activity of the last year, hour by hour, in `activity.go`: `activity.json`, `GET /api/activity`, the work and each scope's spend from the summaries' `spend.hours`; `persist.go` writes it in the background, a versioned envelope with a `.bak`), and serves signed-in browsers the list with each instance's `state`, their changes (`/api/events`), where machines join it (`join.go`, `/api/join`: the hub's addresses, and its secret on a hub with a token) and a proxy that opens any instance in the chat with its token (`proxy.go`); the page is `chat/src/components/hub-view.tsx` with its parts and hooks in `chat/src/components/hub/` (what the rows share in `HubListContext`; the agent open and Issues as pages of the browser's history in `chat/src/lib/hub-route.ts`, `useHubRoute`), its logic in `chat/src/lib/hub.ts` (the instance, its state, the stream's events: `parseHubEvent`) with `hub-groups.ts`, `hub-machines.ts`, `hub-filter.ts`, `hub-format.ts`, `hub-spend.ts`, `hub-work.ts`, `hub-activity.ts` (the overview's heatmap, `hub/activity-card.tsx`), `hub-version.ts` and `hub-order.ts` beside it, its types generated from `lib/hub/hub-schema.json` (`schema.go`) into `chat/src/lib/hub-schema.ts`, what the browser keeps in `chat/src/lib/hub-settings.ts`, and the changes it makes through `chat/src/lib/hub-api.ts`; the chat it opens in a frame draws the instance's bar (`hub/frame-bar.tsx`, from window messages in `chat/src/lib/hub-frame.ts`, read by `parseToFrame` and `parseFromFrame`). The favorite prompts are the first of the hub's settings (`hubSettings`, `store.updateSettings`), kept in the same file (`favorites.go`, `GET`/`PUT /api/favorites`; the file has them in `settings`; the top-level copy of hubs 3.5 to 3.7 is read when `settings` is missing), managed in the page's settings (`hub/settings.tsx`, a dialog with tabs: `hub/favorites-settings.tsx`; `hub/providers-settings.tsx`, its logic in `chat/src/lib/hub-providers.ts`, for the model providers the hub keeps in `providers.json` (`providers.go`, `GET`/`PUT /api/providers`, `POST /api/providers/check` (the editor's Check connection), keys write-only and inherited only at unchanged endpoints, whole-list revisions with stale PUTs returning 409, and `POST /api/providers/sync` for the AgentAPIs); and `hub/github-settings.tsx`, the hub's GitHub App with links to GitHub (`hub/github-app-card.tsx`), Reconnect and Disconnect (`hub/github-dialogs.tsx`), its logic in `chat/src/lib/hub-github.ts`, read once for it and Issues in `chat/src/lib/hub-github-store.ts`, `useHubGitHub`) and sent to the framed chat, whose composer inserts one (`message-input/favorites-menu.tsx`).
- **`lib/sse/`** — Server-sent events as the HTML standard defines them (`Reader`, `Write`), for the hub's streams; `lib/httpapi` writes its own with huma's `sse`.
- **`lib/netaddr/`** — The machine's IPv4 addresses: those other machines may reach it at (the hub's join URLs, `Reachable`), and `Resolver`, the source address of the route to a host (kept 30 s, each lookup bounded by `DialTimeout`). It fills in `{ip}` in `--public-url` for every webhook event, summary and registry entry; the webhook dispatcher looks it up in the background and the events read the last answer.
- **`lib/userconfig/`** — The user's settings file, `~/.agentapi/config.yaml`: `agentapi server` flags by name, below flags and `AGENTAPI_*` variables (`cmd/server/userconfig.go`); `agentapi hub join` writes a hub's webhook into it.
- **`lib/registry/`** — The registry of the AgentAPIs running on a machine (`~/.agentapi/instances`): each server writes its entry while it serves (`--registry`, `--registry-dir`); `agentapi list` and clients that watch many read it.
- **`lib/dispatch/`** — The hub's issue dispatch, which `lib/hub` mounts when `Config.Dispatch` is set (`agentapi hub serve` always sets it): `host.*` events at `/hooks` add the machines (`HostEvent`: each name pinned to the launcher token it first came with, `ForgetHost`/`DELETE /api/hosts/{name}` frees it; reconciling their jobs, adopting the starts the hub lost the answer of and stopping, worktree kept, the jobs no start asked for), `task.*` events add up each job's run cost when both the instance and process `server_id` match and the hub reads that instance, as that run, at an address of the run's machine's launcher URL (`TaskEvent`, with the URL `lib/hub`'s `taskInstanceURL` passes), `POST /api/dispatch` (`MountDispatch`: a signed-in browser or `--dispatch-token`) starts, messages, links and stops jobs on the launchers (`service.go`: a start answers once its job is `starting` on the machine `reserveStart` picked under the lock, and `runStart` calls the launcher in the background, kept in `dispatch.json` as `starts` until it ends; the host choice in `pickHostLocked`, agent switches that keep the worktree, failed background writes stay pending for retry; the last 50 messages of each job with their source, `Job.Messages`), `Subscribe` and `Board` hand the hub's browser stream the machines and jobs after each change (its `dispatch` event), `prompts.go` has the agent's prompts and the cost comment, and `http.go` the session routes (`/api/hosts`, `/api/jobs`, `/api/github*`, the manifest flow `/github/connect`, `/github/callback`, `/github/setup`) and `/api/github/token`, where a launcher signed with the hub's secret gets a job's repository token. It keeps `dispatch.json` and `github-app.json` next to `instances.json`.
- The dispatch's page is the hub's Issues page (`chat/src/components/hub/issues/`, opened from the list header's ◎ or `i` in place of the overview, `issues-view.tsx` with its cards, detail (`issue-detail.tsx`, `issue-status.tsx`, `detail-parts.tsx`), assign menu and `use-dispatch.ts`), its board model in `chat/src/lib/hub-issues.ts` and its calls in `chat/src/lib/hub-dispatch.ts`, which checks each answer; the machines and jobs come only with the stream's `dispatch` event (`useHubStream`), an action's answer standing in for its job until the stream has it as new (`withAnswers`), which feeds the ◎ badge and the list rows' issue chips (`HubListContext.jobs`, `hub/issues/job-chip.tsx`); its types are the hub schema's `Dispatch*`, `Launcher*` and `GitHub*` (`schemaNamer` in `lib/hub/schema.go` prefixes the types of `lib/dispatch`, `lib/host` and `lib/github`). `examples/issue-dispatch/` has the GitHub workflow that turns a repository's events into dispatches.
- **`lib/github/`** — The hub's GitHub App with the standard library only: the manifest conversion, the RS256 JWT, installation tokens for one repository (kept until five minutes before they expire), and the REST calls as the app (`As`: issues, comments, labels, branches).
- **`lib/jsonapi/`** — The JSON plumbing `lib/hub`, `lib/dispatch` and `lib/host` share, standard library only: `Read` (a body of 1 MiB at most, else 400), `Write`, and `Error` (`Errorf`, `IsCode`): a refusal with its HTTP status and a code, which `WriteError` answers as `ErrorBody`, `{"code", "message", "error"}` (`error` repeats `message`; `StatusCode` is the code of an error without one of its own). Every error the hub answers has that shape; `ReadError` reads it.
- **`lib/host/`** — `agentapi host serve`, the launcher a hub dispatches GitHub issues to (spec: `docs/specs/issue-dispatch.zh-TW.md`). `Launcher` (`launcher.go`) starts a job: the repository (scanned in `repos.go`, or cloned), a worktree on `agent/issue-<n>` beside it (`<repo>.worktrees/<n>`), then an `agentapi server` in a session of its own (`process_*.go`) with a state database per run, the shared instance token, and an environment without AgentAPI's variables (`procenv`), with the job's git setup in `GIT_CONFIG_COUNT` entries. It keeps the jobs in `~/.agentapi/jobs.json` (`jobs.go`), takes over the ones still running after a restart and starts again those that exited, after 5 s, 15 s, 45 s, 2 min, then 5 min (`restartDelays`; the restarts kept in `jobs.json`), failing one that exits again after 5 restarts in 30 minutes. A start goes on when the hub's request ends (`StartTimeout`); if its initial metadata can't be saved, the child is stopped rather than reported as started. The process's `server_id` distinguishes restarts in `jobs.json`, and `Jobs` reports the jobs still being prepared as `starting`, without an AgentAPI. `server.go` is the API for the hub behind the host token (`/host`, `/jobs`) and the unix socket (`host.sock`) where the jobs' git credential helper and gh shim get a GitHub token (`credentials.go`: the hub's tokens through `HubCredentials` in `hub.go`, or one token from `github-token-file`; each job keeps which). `hub.go` also sends the hub the signed `host.*` events (`reportLoop`); the jobs' AgentAPIs read the launcher's config file and send `task.*` events too. It reads the `host` section of `~/.agentapi/config.yaml`, which `agentapi server` skips (`config.go`).
- **`lib/atomicfile/`** — `Write` replaces a file at once (0600): a temporary file, synced before it is renamed into place and the directory synced after, so a crash leaves the old data or the new. `lib/userconfig`, `lib/registry` and `lib/hub` write their files with it.
- **`lib/selfupdate/`** — Installs the latest release of k1dav-c/agentapi in place of the program (`agentapi update`, `POST /update`): the GitHub lookup, the binary for the platform, its check against the release's `checksums.txt` and that it runs as that version, and the rename under a lock file next to the program (`Install`); `Program.Blocked` says why the user can't replace the program, with the one-time fix. `selfupdatetest` serves a fake release for tests.
- **`lib/shellterm/`** — The shared shell terminal (`GET /terminal`).
- **`lib/htmlpreview/`** — Turns an HTML file into a page that shows by itself (its stylesheets, scripts and images inlined as `data:` URLs), for the file viewer's preview.
- **`lib/handoff/`** — The types of the human reply protocol (`GET /handoff`, `POST /handoff/reply`).
- **`lib/filelock/`** — An exclusive lock on a file, which AgentAPIs on one machine take in turn: updating the program, an agent CLI updating itself.
- **`lib/logctx/`** — The logger in a `context.Context`, and `--log-level` parsing.
- **`lib/util/`** — `OpenAPISchema`, which registers a string type's values as an enum in the OpenAPI schema.
- **`skills/`** — Agent skills for users of AgentAPI (`agentapi-hub-join`: an agent joins its machine to a hub, documented in `docs/hub.md`); they install into `~/.claude/skills/` and aren't for working on this repository.
- **`cmd/`** — CLI commands via cobra/viper. Includes `server` (which restarts in place on SIGUSR2, and after an update through its API with `--allow-update`), `list` (the AgentAPIs in the registry, with their summaries), `hub` (`serve`: the hub; `join`, `leave`, `status`: connecting a machine's AgentAPIs to a hub), `host` (`serve`: the launcher; `install`, `uninstall`: its systemd user service, `KillMode=process` so the jobs outlive a restart of it; `status`; the hidden `git-credential` and `gh-token` the jobs run), `restart` (has the registered AgentAPIs restart in place, e.g. into an updated binary), and `update` (`--restart` restarts them after it) subcommands.

### The native transport

AgentAPI speaks Claude Code's stream-json, `codex app-server` JSON-RPC or `pi --mode rpc` directly. Adapters must follow the `Sink` contract in `lib/native/types.go` (no concurrent Sink calls; message IDs unique across adapters of one factory). There is no `--transport` flag.

### Adding a new agent type

1. Write its native adapter under `lib/native/<agent>`: a `native.Factory` and an `Adapter` that follows the `Sink` contract
2. Add the `AgentType` constant in `lib/instanceapi/instance.go`
3. Add its case in `nativeFactory` (`cmd/server/native.go`) and its alias in `agentTypeAliases` (`cmd/server/server.go`)
4. If it keeps session logs, add their format in `lib/agentlog/<agent>log` and read them in `lib/sessions`
5. Add display name in `chat/src/lib/agents.ts`

### Exhaustive switch/map enforcement

The `exhaustive` golangci-lint checker covers switches and maps. When adding an `AgentType` or enum
value, update every switch and map literal over that type to pass lint.

## Conventions

- Versioning: `internal/version.Version` stays `0.0.0-dev` in source; builds stamp the real version via `-ldflags -X` (`make build` uses the latest `vX.Y.Z` tag). Releases are cut by CI on push to `main` from Conventional Commit messages (`next-version.sh`), so use `feat:`/`fix:`/`feat!:` prefixes. The Release workflow runs the tests (`go-test.yml`) on the commit first and releases only if the Linux jobs pass, so a `main` that fails them doesn't release
- OpenAPI schema is auto-generated: run `make gen` and commit `openapi.json`. Don't redirect `server --print-openapi` into the file yourself: it escapes `<`/`>` as `\u003c`/`\u003e`, `make gen` doesn't, and the Release workflow fails on the difference. Then run `bun run gen:api` in `chat/` and commit `chat/src/lib/api-schema.ts`, the chat's API types (a chat test fails until they match)
- The hub's API isn't huma's, so `make gen` writes its wire types to `lib/hub/hub-schema.json` (`hub.Schema`: an OpenAPI document with only `components.schemas`, from the Go types through huma's registry, and `HubLimits`, the limits the page checks; `TestHubSchema` fails until it is committed). `bun run gen:api` turns it into `chat/src/lib/hub-schema.ts` (`chat/scripts/hub-schema.ts`: openapi-typescript's types and `hubLimits`); the hub page's types come from it, not by hand
- The chat UI build output goes to `lib/httpmw/chat/` with a base-path placeholder that gets replaced at runtime
- AgentAPI-specific environment variables use the `AGENTAPI_` prefix (e.g., `AGENTAPI_ALLOWED_HOSTS`)
- Server defaults: port 3284, chat at `/chat`, docs at `/docs`
- User docs: `README.md` is the overview (features, quickstart, agents, an index of the guides); the guides are in `docs/`: `chat-ui.md`, `agents.md` (the native transport and each agent), `providers.md`, `api.md` (the conversation API, integrations and the endpoint reference), `security.md`, `cli.md`, `hub.md` and `architecture.md`. The Resource usage tables in `docs/cli.md` come from `bun scripts/measure-resources.mjs` (Linux; `native-demo` unless `--agents` names real agents). Each has a `.zh-TW.md` twin that mirrors it section by section: change both together, and keep headings, which other pages link to by anchor. Docs links and twins are checked by `go test ./internal/docscheck`: every relative link, image and `#anchor` in the tracked Markdown resolves (GitHub's heading slugs), and each twin has the same heading levels in order, fenced code blocks per section, images in order and linked files
